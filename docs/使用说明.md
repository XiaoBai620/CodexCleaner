# Codex 本地清理台 · 使用说明

这是一个由你手动控制的 Windows 桌面工具。它不会自动或定时删除任何内容，也没有开机自启。核对预览后点击一次确认即可删除，成功后不保留恢复副本。它根据已验证的存储结构独立制作，不是 Codex 官方功能。

## 开始使用

1. 双击 `CodexCleaner.exe`。首次运行如果提示缺少 .NET，按提示安装“.NET 10 桌面运行时”（Windows Desktop Runtime）后再打开。窗口顶部显示 Codex 运行状态，将鼠标停在状态说明上可查看数据目录。
2. 完全退出 Codex 桌面应用和 Codex 命令行。工具每隔几秒自动检查一次，退出后顶部会变成“准备就绪”。浏览器插件的通信程序 `extension-host` 和商店版的沙箱服务会被系统自动重启，它们不写聊天数据，不需要结束。
3. 按标题或聊天 ID 搜索，也可按状态筛选。点击一行，在右侧查看完整标题、会话 ID、路径和处理原因；点击“展开”可在独立窗口阅读完整详情，也可直接复制。勾选框用于选择清理内容。“全选结果”只选择当前筛选中可清理的聊天，再点一次可取消这批选择。更换筛选不会清空已有选择，统计会同时显示总已选数与筛选外已选数；可用“清空选择”取消全部选择。
4. 右侧附加范围中的“全部本地记忆”“共享输入历史与日志”默认不勾选。需要影响所有聊天的全局清理时，再主动勾选对应项。
5. 点击“预览清理范围”，在确认窗口中展开聊天、数据库和文件明细；点选项目可在右侧阅读并复制完整说明。确认范围后点击“确认清理”。Codex 仍在运行、状态无法确认或预览过期时，确认按钮不可用。
6. 完成后再启动 Codex。

列表里标为“文件已缺失”的聊天也可以勾选，用来清除残留记录。受保护、无法勾选的聊天仍可点选查看详情，例如自动化引用或数据库结构未通过检查的具体原因。

## 版本更新

每次启动后，工具会在后台向 GitHub 检查一次最新正式版本，不影响读取和清理本地记录。也可以点击窗口中的“检查更新”手动重试；预发布版本不会触发更新提示。

发现比当前版本更新的正式版本时，窗口会持续显示新版提示。点击“前往更新”会打开本项目的 GitHub 发布页。下载新的 `CodexCleaner.exe` 后，关闭旧程序再替换即可；工具不会自动下载、安装或替换文件。

断网、请求超时或 GitHub 暂时不可用时，仍可继续使用本地清理功能，稍后再检查更新。

## 会话路径异常时

旧版提示“会话文件不在已验证的 sessions / archived_sessions 目录”，表示数据库保存的会话路径不符合工具识别的本地会话目录规则。它不等于已经确认文件丢失；可能是旧路径、迁移后的路径或其他存储形式。

这类记录以及未提供会话路径的记录，会显示“仅清理记录”。勾选并预览后，可以清理该聊天在已验证数据库、索引和桌面状态里的本地记录与关联数据。工具不会根据异常路径查找、读取或删除原会话文件；确认窗口会单独列出保留的会话文件。原文件以后被 Codex 重新导入时，聊天可能重新出现。

如果原路径恰好也是本次其他清理操作要修改的文件，例如同时选择清空全部记忆，而原路径位于记忆目录，工具会拒绝该组合并说明冲突。可取消相关附加清理后重新预览。数据库、自动化以及受控目录内的链接保护仍然生效；设备路径和数据流等无法安全确认的特殊路径也保持受保护。

如果之前删除后，在 Codex 里遇到项目或归档错误，点击“检查失效引用”。它只清除指向已不存在聊天的本机引用，保留现存聊天与项目；它不能重建已经丢失的聊天正文。数据库里仍存在的异常路径记录，需要在列表中勾选“仅清理记录”后预览处理。

## 清理范围

本工具按整条聊天清理，不提供逐条消息或逐句记忆编辑。合并后的记忆可能混合多条聊天的内容，无法可靠地拆分到单个聊天；需要时请选择“全部本地记忆”。

清空记忆不会关闭 Codex 的记忆功能。继续启用记忆并保留旧聊天时，之后可能再次生成记忆；如果想避免，请先在 Codex 的设置里关闭记忆。

派生或复制出的聊天是独立记录，其中复制的上下文不会因为删除原聊天而消失。

| 位置 | 作用与处理方式 |
|---|---|
| `sessions/`、`archived_sessions/` | 原始会话记录。只删除数据库准确关联、且文件内会话 ID 也匹配的文件；孤立文件保留。 |
| `state_5.sqlite` | 聊天标题、会话路径、已读回执和项目索引。按所选聊天删除，项目保留。 |
| `thread_history_1.sqlite` | 消息、轮次和工具输出。 |
| `memories_1.sqlite`、`memories*/` | 记忆提取结果和生成的记忆文件。 |
| `logs_2.sqlite` | 运行与反馈日志，可能包含聊天片段。按聊天删除，或选择全部清空。 |
| `goals_1.sqlite`、`queue_1.sqlite` | 持续任务目标、待处理消息。 |
| `sqlite/codex-dev.db` | 桌面聊天目录、时间线、收件箱等。只处理本机记录，保留其他主机的数据。 |
| `session_index.jsonl`、`history.jsonl` | 会话索引和命令行输入历史，按准确的会话 ID 删除对应行。 |
| `.codex-global-state.json` 及 `.bak` | 桌面界面状态。只修改识别出的本机聊天字段，其他设置保持不变。 |
| 配置、规则、插件、技能、登录信息、项目、自动化定义 | 保留。 |
| 普通日志、语音和听写、浏览器状态等 | 归属无法可靠确定，保留。 |

“保留”只表示不在清理范围，不代表其中一定没有个人数据。

## 删除与中断

确认后执行普通的文件删除和数据库记录删除，无法通过本工具撤销，也不是 SSD 或磁盘的安全擦除。云端记录、云端记忆、系统还原点和外部备份不受影响。

为了避免多个数据库只改了一半，执行期间会在 `%LOCALAPPDATA%\CodexCleaner\Transactions` 暂存修改前的副本。成功后自动删除；遇到错误时自动还原，校验通过后同样删除。清理进行中工具会阻止关闭窗口。

如果断电、强制结束进程，或自动还原本身失败，工具会保留故障材料并显示具体位置，同时禁止后续清理，避免覆盖数据。这时请保持 Codex 关闭，先处理故障材料，不要删除事务目录来绕过保护。

读取部分 SQLite 数据库时，可能在系统临时目录短暂创建 `codex-cleaner-inspect-*` 只读副本，用完立即删除；异常中止时可能残留，其中可能包含聊天内容，请勿上传或分享。

## 何时会拒绝清理

- 检测到 Codex 正在运行（桌面版、命令行，或数据目录内的 Codex 程序）。进程检测无法覆盖 WSL、远程设备或第三方程序；如果它们也写入这个目录，需要你自己停止。
- 任何一个数据库的结构与已验证版本不同。Codex 升级后出现这种情况时，需要更新本工具。
- 文件删除路径不安全，例如位于数据目录外，或存在符号链接、目录联接、硬链接。部分异常路径记录可改为“仅清理记录”，但不会放宽文件访问限制。
- “仅清理记录”要求保留的原路径与本次其他文件或数据库修改范围重合。
- 预览后数据发生了变化，或预览已超过 15 分钟。
- 上次操作留下了未处理的故障材料。

## 数据位置

数据目录默认使用环境变量 `CODEX_HOME`，未设置时为 `%USERPROFILE%\.codex`。聊天与记忆的读取、预览和清理都在本机完成。更新检查会连接 GitHub 的公开版本接口，仅获取发布信息；不上传聊天、记忆、文件路径、登录信息或本地文件。
