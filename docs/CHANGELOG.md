# 更新记录

## 3.5.1

- 统一会话筛选的展开列表与主界面风格：浅灰圆角边框、圆角悬停底色和当前选项勾选标记；六个筛选项完整显示，保留原有键盘选择方式。
- 更新提醒、完整说明和错误详情采用一致的圆角阅读区、按钮间距与黑灰进度条；调整窄窗口布局，说明文字可选择、复制，保留列表缩进和代码内容。
- 修复取消下载后模态窗口提前关闭的问题，可在原窗口重新下载；忽略上一轮下载的延迟进度，失败时可查看完整错误详情并重试。
- 增加使用隔离模拟数据的更新体验工具，方便测试更新摘要、下载进度、取消与重试流程。

## 3.5.0

- 新版提示直接展示版本号与简要更新内容；新增“查看并更新”窗口，可阅读并复制完整更新说明，保留“手动下载”入口。
- 支持在程序内下载新版 exe，显示下载进度并可取消。下载完成后核对 SHA-256、Windows 64 位程序格式、产品名称和目标版本；附件缺失、来源异常或校验失败时不替换程序。
- 校验通过后等待当前程序退出，再替换并重新启动；替换或启动失败时尝试还原旧程序，无法恢复时保留故障材料并提示处理，不保证断电后自动恢复。清理、恢复等操作进行中禁用更新入口。
- 3.3.0、3.4.0 等旧版需先从发布页下载并手动替换一次 exe，之后可使用内置更新。更新只替换程序，不修改聊天、记忆或清理备份；同步修正文档中清理成功后不保留恢复副本的过时说明。

## 3.4.0

- 删除前自动保留所选聊天的行级 SQLite 备份和原会话文件，覆盖七个已验证数据库、分段文件、压缩副本及关联索引；运行中清理也必须先完成备份并在删除前复查内容。主界面新增“备份与恢复”，显示占用大小、按聊天选择、全选可恢复项和删除旧备份；读取、预览、恢复及删除在后台执行。
- 恢复要求退出 Codex，并占用聊天写入锁与会话整理锁；核对数据库结构和迁移版本，跳过已存在聊天，增量合并索引，拒绝路径、内容及分叉依赖冲突。全局记忆、共享历史与日志独立按组恢复，普通聊天恢复不覆盖桌面置顶、草稿和窗口状态。运行中部分删除保留故障备份并阻止继续写入，退出后通过独立入口核对恢复；恢复失败沿用事务副本回滚，无法验证时保留故障材料。
- 运行中索引改写在同一文件锁内先保存完整前后内容及摘要，空间估算按原索引长度的两倍计入；可捕获的写入异常会在持锁期间还原并校验。故障恢复拒绝无法判定的半写或后续修改，只允许完整前后状态及其后追加的无关有效记录。启动只检查轻量备份清单，不在每次 Snapshot 中散列全部备份内容。
- 备份恢复新增 51 个合成用例；最终完整 Release 测试 219/219 通过，0 失败、0 跳过，用时 2 分 18 秒，编译无告警。已检查正常备份已选、故障备份和最小 860×580 窗口三张实际界面截图，列表、说明和按钮完整可见，状态符合预期。真实数据删除/恢复及实机断电一致性未验证。
- 启动实测（2026-11-09）：在约 1.11 GB 的真实数据副本上，7 个数据库由 SQLite backup API 复制；Snapshot 包含 15 条聊天、15 个会话文件，首次 191.352ms，后续四次 49.831–53.932ms。首次分段：数据库结构 83.408ms、自动化查询 5.295ms、聊天查询 2.232ms、会话扫描 68.089ms、锁检测 1.704ms、消息计数 16.083ms、路径检查和文件大小汇总 9.668ms。没有一段超过 300ms，因此没有做性能代码优化，优化后数据不适用；引用检查和使用中检测均保留。系统缓存未清空，不能视为冷启动；副本未复制成功的 18 个文件均为运行中锁/守卫，不能模拟真实进程锁占用，锁竞争由合成测试验证。当前大小列来自会话文件而非消息 JSON 字节数。
- 对照 DevinCleaner，将工具参数与结果保留上限分别提高到 200,000 字符；工具仍默认折叠，展开可显示引擎保留的全文。2026-11-09 只读统计 2,627 条历史条目，命令执行类 JSON 最大 77,769 字符、P99 为 58,332（JSON 字符数，不等同于工具字段长度）。真实副本最长对话含 1,626 条记录、4,007,423 个 JSON 字符，首次打开 454ms，后续 202/179ms；最长工具结果 65,496 字符，首次展开 60ms，内容完整，首次界面计时消息最大间隔 299ms。该历史投影已没有主聊天记录，测量直接用其 ID 打开同一个对话窗口；不代表主列表能访问该孤立记录。
- 参照 DevinCleaner，在离线清理、运行中清理和失效引用修复中显示锁定、备份、校验、逐库删除、文件处理与刷新阶段；状态栏每 500ms 更新累计执行秒数，确认窗口的等待时间不计入。保持运行中清理最后提交聊天主库的顺序。

## 3.3.0

- Codex 运行时也能删除没在使用的聊天：按 `thread-writer-locks\<id>.lock` 是否被锁住识别“使用中”（与 Codex 自身的写入锁协议一致，不依赖进程号），这类聊天不能勾选，其余可直接预览清理。执行时先占用所选聊天的写入锁和会话整理锁，阻止 Codex 同时打开或压缩它们；数据库逐个在事务中删除，最后删除聊天主记录，出错时只回滚当前库，聊天保留在列表中可重试。运行期间不修改桌面界面状态，退出后用“检查失效引用”清除残留；“全部本地记忆”“共享历史与日志”仍需先退出 Codex。
- Codex 退出时的清理也会占用所选聊天的写入锁，防止清理中途启动的 Codex 打开它们。
- 修复两处漏删：同一聊天的分段会话文件和 Codex 压缩的 `.jsonl.zst` 副本现在会一起删除；被其他分叉聊天引用为历史来源的聊天会拒绝单独删除（与 Codex 的删除规则一致），需一并选择分叉聊天。
- 新增只读“查看对话”窗口（移植自 DevinCleaner）：按 Codex 的历史投影显示提问、回复、思考摘要和命令/文件修改等工具调用，可拖选复制。双击列表行也能打开。
- 列表新增“消息 · 大小”列和“使用中”筛选。
- 图标改为 ChatGPT 标志（白底黑色花结），由 `scripts/make_icon.py` 生成；窗口左上角同步显示。
- 界面改为 ChatGPT 风格：近白画布、白色卡片与大圆角、胶囊形按钮和筛选框、黑色主按钮、灰色标签胶囊，绿色只用于“准备就绪”等可执行状态；确认窗口和对话窗口使用同一配色。
- 仍是单个 `CodexCleaner.exe`（依赖库已打包在内，不需要附带 dll），需要 .NET 10 桌面运行时。

## 3.0.0

- 改为原生 Windows 桌面程序（C# / WinForms）：单个约 3 MB 的 `CodexCleaner.exe`，运行在 .NET 10 桌面运行时上，不再需要 Node.js，不再启动本地网页服务、占用端口或打开浏览器。
- 清理引擎用 C# 重写，保留全部安全机制：结构指纹校验、预览数据指纹、跨进程写入锁、事务备份与自动回滚、路径与链接防护、自动化引用保护。
- 进程检测改为检查程序路径：新增识别商店版 Codex 应用、`codex-command-runner` 和数据目录内的 Codex 程序。旧版只按进程名判断，这些程序运行时会被误判为“已退出”。商店版常驻的沙箱服务和浏览器插件的通信桥 `extension-host` 不写聊天数据，且会被系统自动重启，不计入。
- 移除“文件用途”浏览页、命令行参数、启动脚本、网页界面和本地 HTTP 接口；文档集中到 `docs/`。
- “清空全部本地记忆”“清空共享输入历史与日志”默认勾选。
- 新增程序图标；推送版本标签后由 CI 自动测试、构建并发布 exe 和 `SHA256SUMS.txt`。
- 适配 2026-10-31 检查到的 Codex 数据库结构：`state_5.sqlite`（迁移 62）、`thread_history_1.sqlite`（迁移 8）和 `sqlite/codex-dev.db`。旧指纹导致全部聊天无法识别。
- 删除聊天时同步删除 `thread_read_receipts`、`guardian_review_feedback` 中的对应记录。
- 删除父聊天时，附着的子聊天会置空 `attached_thread_parent_id` 并保留；“检查失效引用”也会修复这两类残留。
