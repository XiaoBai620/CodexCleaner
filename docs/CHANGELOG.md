# 更新记录

## 3.3.0

- Codex 运行时也能删除没在使用的聊天：按 `thread-writer-locks\<id>.lock` 是否被锁住识别“使用中”（与 Codex 自身的写入锁协议一致，不依赖进程号），这类聊天不能勾选，其余可直接预览清理。执行时先占用所选聊天的写入锁和会话整理锁，阻止 Codex 同时打开或压缩它们；数据库逐个在事务中删除，最后删除聊天主记录，出错时只回滚当前库，聊天保留在列表中可重试。运行期间不修改桌面界面状态，退出后用“检查失效引用”清除残留；“全部本地记忆”“共享历史与日志”仍需先退出 Codex。
- Codex 退出时的清理也会占用所选聊天的写入锁，防止清理中途启动的 Codex 打开它们。
- 修复两处漏删：同一聊天的分段会话文件和 Codex 压缩的 `.jsonl.zst` 副本现在会一起删除；被其他分叉聊天引用为历史来源的聊天会拒绝单独删除（与 Codex 的删除规则一致），需一并选择分叉聊天。
- 新增只读“查看对话”窗口（移植自 DevinCleaner）：按 Codex 的历史投影显示提问、回复、思考摘要和命令/文件修改等工具调用，可拖选复制。双击列表行也能打开。
- 列表新增“消息 · 大小”列和“使用中”筛选。
- 新图标：黑底白色对话框加擦除笔画，由 `scripts/make_icon.py` 生成。

## 3.2.0

- 启动后在后台检查 GitHub 上的最新正式版本；发现新版本时持续显示更新提示，也可手动点击“检查更新”。
- 点击“前往更新”才会打开本项目的 GitHub 发布页，由用户下载替换程序；不会自动下载安装。断网、超时或检查失败不影响本地清理。
- 更新检查仅请求公开的版本信息，不上传聊天、记忆、路径、登录信息或本地文件。
- 本次发布包含此前尚未发布到 GitHub Release 的 3.1.0 改动：异常会话路径的“仅清理记录”、新版列表与详情界面、筛选与选择统计，以及默认关闭全局清理选项。完整变化见下节。
- 发布流程改用 Python 校验版本、提取更新记录和生成 SHA-256 校验文件。

## 3.1.0

- 修复异常会话路径记录无法清理的问题：新增明确的“仅清理记录”方式，移除本地记录与已识别关联，不按异常路径访问原会话文件；默认完整删除仍拒绝异常路径。
- 记录清理继续保留数据库、自动化、链接与预览指纹保护；原路径与其他清理目标重合时拒绝该组合，防止保留说明与实际操作冲突。
- 修正 Windows 下正常会话路径大小写不同导致的误拒。
- 重做主窗口为会话列表与右侧详情、清理范围布局，调整配色、间距、行高和按钮层级；完整标题、路径和限制原因可持续查看与复制。
- 增加状态筛选、清除搜索和清空选择；“全选结果”与筛选联动，统计同时显示总已选和筛选外已选，避免隐藏清理范围。
- 全部本地记忆、共享输入历史与日志改为默认不勾选，需要时主动选择。
- 重做确认窗口，分别列出聊天、数据库、文件、附加范围与保留的会话文件，支持查看和复制完整项目说明。

## 3.0.0

- 改为原生 Windows 桌面程序（C# / WinForms）：单个约 3 MB 的 `CodexCleaner.exe`，运行在 .NET 10 桌面运行时上，不再需要 Node.js，不再启动本地网页服务、占用端口或打开浏览器。
- 清理引擎用 C# 重写，保留全部安全机制：结构指纹校验、预览数据指纹、跨进程写入锁、事务备份与自动回滚、路径与链接防护、自动化引用保护。
- 进程检测改为检查程序路径：新增识别商店版 Codex 应用、`codex-command-runner` 和数据目录内的 Codex 程序。旧版只按进程名判断，这些程序运行时会被误判为“已退出”。商店版常驻的沙箱服务和浏览器插件的通信桥 `extension-host` 不写聊天数据，且会被系统自动重启，不计入。
- 移除“文件用途”浏览页、命令行参数、启动脚本、网页界面和本地 HTTP 接口；文档集中到 `docs/`。
- “清空全部本地记忆”“清空共享输入历史与日志”默认勾选。
- 新增程序图标；推送版本标签后由 CI 自动测试、构建并发布 exe 和 `SHA256SUMS.txt`。
- 适配 2026-10-31 检查到的 Codex 数据库结构：`state_5.sqlite`（迁移 62）、`thread_history_1.sqlite`（迁移 8）和 `sqlite/codex-dev.db`。旧指纹导致全部聊天无法识别。
- 删除聊天时同步删除 `thread_read_receipts`、`guardian_review_feedback` 中的对应记录。
- 删除父聊天时，附着的子聊天会置空 `attached_thread_parent_id` 并保留；“检查失效引用”也会修复这两类残留。
