# 架构与兼容性

浏览器通过带临时凭证的本机 HTTP API 调用 `server.cjs`。服务不接受任意 SQL 或任意删除路径；清理引擎只生成固定规则的预览计划，执行时通过计划 ID 取回已验证的操作。

## 数据结构

以下名称及 `lib/cleaner.cjs` 中的结构指纹来自 2026-10-31 的兼容性检查，不是 Codex 对外保证的稳定 API，也不能推导出所有 Codex 发布版本都受支持。

| 数据库 | 处理对象 |
|---|---|
| `state_5.sqlite` | 聊天记录及直接关联表（含已读回执、审核反馈）；被删父聊天的子聊天置空 `attached_thread_parent_id` 后保留；项目定义保留 |
| `thread_history_1.sqlite` | 消息、轮次和实时历史投影 |
| `memories_1.sqlite` | 直接提取记忆；明确全选时清理整理任务 |
| `logs_2.sqlite` | 所选聊天日志；明确全选时清理全部数据库日志 |
| `goals_1.sqlite` | 聊天目标及延续状态 |
| `queue_1.sqlite` | 待处理消息和队列版本 |
| `sqlite/codex-dev.db` | 已识别的本机聊天目录、收件箱、时间线等引用 |

`test/fixture-schema.json` 保存结构定义；`test/fixture.cjs` 在独立临时目录创建所有数据行。指纹覆盖表和触发器定义，保留严格的 SQL 结构匹配；不为适配新版而自动忽略差异。

原始会话文件必须位于受控的 `sessions/` 或 `archived_sessions/` 下，并与聊天 ID 匹配。正文缺失时可以清理索引，但不会尝试重建正文。未知文件、没有可靠归属的孤立会话、项目导出与语音资料保留。

桌面 JSON 状态按明确字段处理：项目迁移、归档/置顶、草稿、未读和最近文件等引用必须满足已识别的本机归属条件；不会递归删除任意匹配 UUID 的字符串。

## 写入流程

1. 读取并验证结构、路径、自动化引用和当前数据，生成 15 分钟有效的计划。
2. 前后检查数据指纹，防止预览混合不同时间的数据；执行时再次检查。
3. 获取实例互斥及跨进程事务锁，确认 Codex 的已知 Windows 进程已退出。
4. 备份将修改的数据库和文件，取得 SQLite 写锁，核对计划与备份。
5. 应用固定 SQL 与文件操作，提交后校验结果，移除成功事务的副本。
6. 可处理错误触发回滚；验证恢复成功才删除事务副本。无法验证时保留材料并阻止后续写入。

多个 SQLite 文件及普通文件之间没有操作系统级原子提交。事务副本用于自动回滚已捕获的失败，不能保证断电后无需人工处理。引擎拒绝新的清理覆盖未解决的事务。

进程名检测与文件指纹也无法防御恶意的同账户并发文件替换。使用者须停止所有写入目标目录的程序；不能把此工具作为隔离不可信本地进程的安全边界。

## 目录与保留材料

- 数据根：`CODEX_HOME` 或 `%USERPROFILE%\.codex`，可用 `--data-root` 显式指定。
- 事务根：`%LOCALAPPDATA%\CodexCleaner\Transactions`，可用 `--transaction-root` 指定。事务根与数据根不可互相包含。
- 启动日志：`%LOCALAPPDATA%\CodexCleaner`，正常启动不记录访问凭证。
- 临时只读检查副本：系统临时目录下的 `codex-cleaner-inspect-*`，正常关闭数据库后删除；进程异常终止可能留下副本。
- 自动测试：系统临时目录下 `codex-cleaner-test-*` 的虚构数据；不是生产事务材料。

不要把这些目录提交或上传。异常事务的界面提示包含具体位置；保持所有数据写入者退出，通过明确的文件/数据库校验处理故障，不要以删除锁或事务目录来绕过保护。

若进程在检查旧写入锁时被强制终止，可能留下事务根下的 `.mutation-reclaim.lock`。工具无法验证这次检查是否完成时会阻断写入，并在错误中显示完整路径。这类情况需要人工核对原 `.mutation.lock`、进程和事务目录；工具不会自动删除无法验证的锁。

## 验证边界

自动测试验证合成结构上的正常删除、保留内容、关联修复、并发变化与故障回滚，不会对真实用户记录执行清理。浏览器验收使用虚构聊天和模拟视口。没有覆盖所有硬件断电、文件系统、第三方写入者或未来 Codex 数据格式。
